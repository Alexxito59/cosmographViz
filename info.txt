ОБЩЕЕ ОПИСАНИЕ
--------------------------------------------------------------------------------
Веб-приложение для визуализации команд/графа соавторства из базы данных LIS.
Проект представляет собой одностраничное веб-приложение с FastAPI бэкендом и
интерактивной визуализацией графа соавторства с использованием библиотеки Cosmograph.

ТЕХНОЛОГИЧЕСКИЙ СТЕК
--------------------------------------------------------------------------------
Backend:
  - FastAPI (веб-фреймворк, версия приложения: 0.1.0)
  - Uvicorn (ASGI сервер)
  - DuckDB (база данных, read-only режим)

Frontend:
  - Vanilla JavaScript (ES modules)
  - Cosmograph 2.0.0 (@cosmograph/cosmograph) - библиотека для визуализации графов
  - Встроенный CSS (без внешних стилей)
  - Одностраничное приложение (SPA)

БАЗА ДАННЫХ
--------------------------------------------------------------------------------

Режим: read-only
Путь к БД определяется в main.py:
  PROJECT_ROOT = APP_DIR.parent.parent
  DB_PATH = PROJECT_ROOT / "lis.duckdb"

Схема базы данных (выведена из SQL запросов):
  - teams: period (TEXT), team_id (INT), author_id (INT), status (TEXT: 'core'/'periphery')
  - authors: id (INT), lastname (TEXT), givenname (TEXT)
  - docs: eid (TEXT/INT), title (TEXT), year (INT)
  - auth_doc: doc_id (TEXT/INT), auth_id (INT), auth_seqn (INT)

API ENDPOINTS (FastAPI)
--------------------------------------------------------------------------------

GET /
  Описание: Возвращает главную HTML страницу (index.html)
  Ответ: FileResponse

GET /favicon.ico
  Описание: Обработка favicon (возвращает 204 No Content)
  Ответ: Response (status_code=204)

GET /api/periods
  Описание: Получить список всех доступных периодов (скользящих окон)
  Ответ: JSON {"periods": ["2023-2025", ...]}
  SQL: SELECT DISTINCT period FROM teams ORDER BY period

GET /api/teams
  Параметры:
    - period (required): строка формата "YYYY-YYYY" (например, "2023-2025")
    - query (optional): фильтр по имени/фамилии автора
  Описание: Получить список команд с фильтрацией
  Ответ: JSON {
    "teams": [
      {
        "team_id": int,
        "authors_count": int,
        "core_count": int,
        "periphery_count": int,
        "sample_authors": "Фамилия Имя, ..." (первые 3 автора)
      }
    ]
  }
  SQL: Сложный запрос с CTE, фильтрацией по авторам, агрегацией статистики

GET /api/graph
  Параметры:
    - period (required): строка формата "YYYY-YYYY"
    - max_authors_per_doc (optional, default=100): максимальное количество авторов
      на документ (0 = без ограничения, помогает избежать огромных клик)
    - include_single_pub (optional, default=False): включать авторов с 1 публикацией
  Описание: Получить данные графа соавторства (узлы и рёбра)
  Ответ: JSON {
    "nodes": [
      {
        "id": "author_id",
        "lastname": "Фамилия",
        "givenname": "Имя",
        "pubs": int (количество публикаций)
      }
    ],
    "edges": [
      {
        "source": "author_id_1",
        "target": "author_id_2",
        "weight": int (количество совместных публикаций)
      }
    ]
  }
  SQL: Два запроса - для узлов и для рёбер, фильтрация по периоду и параметрам

GET /api/teams/{team_id}
  Параметры:
    - team_id (path): ID команды
    - period (required query): строка формата "YYYY-YYYY"
  Описание: Получить детальную информацию о команде (авторы и публикации)
  Ответ: JSON {
    "authors": [
      {
        "id": int,
        "lastname": "Фамилия",
        "givenname": "Имя",
        "status": "core" | "periphery"
      }
    ],
    "publications": [
      {
        "doc_id": "eid",
        "title": "Название",
        "year": int,
        "authors": [
          {
            "id": "author_id",
            "lastname": "Фамилия",
            "givenname": "Имя",
            "status": "core" | "periphery" | "other",
            "seq": int (порядковый номер автора)
          }
        ]
      }
    ]
  }
  SQL: Два запроса - для авторов команды и для публикаций команды в периоде

GET /api/authors/{author_id}/teams
  Параметры:
    - author_id (path): ID автора
    - period (required query): строка формата "YYYY-YYYY"
  Описание: Получить список команд, в которых состоит автор в указанном периоде
  Ответ: JSON {
    "author_id": "author_id",
    "period": "YYYY-YYYY",
    "teams": [
      {
        "team_id": int,
        "author_status": "core" | "periphery",
        "authors_count": int,
        "core_count": int,
        "periphery_count": int,
        "sample_authors": "Фамилия Имя, ..." (первые 3 автора)
      }
    ]
  }
  SQL: Сложный запрос с CTE для поиска команд автора и статистики

GET /api/teams/{team_id}/graph
  Параметры:
    - team_id (path): ID команды
    - period (required query): строка формата "YYYY-YYYY"
    - max_authors_per_doc (optional, default=100): максимальное количество авторов
      на документ (0 = без ограничения)
  Описание: Получить граф команды с окружением (все авторы публикаций команды)
  Ответ: JSON {
    "nodes": [
      {
        "id": "author_id",
        "lastname": "Фамилия",
        "givenname": "Имя",
        "pubs": int (количество публикаций),
        "status": "core" | "periphery" | null (null для окружения)
      }
    ],
    "edges": [
      {
        "source": "author_id_1",
        "target": "author_id_2",
        "weight": int (количество совместных публикаций)
      }
    ]
  }
  Особенности:
    - Включает всех авторов публикаций команды (не только членов команды)
    - Узлы команды имеют status (core/periphery)
    - Узлы окружения имеют status = null
    - Рёбра соединяют всех соавторов публикаций команды
  SQL: Два запроса - для узлов (команда + окружение) и для рёбер

FRONTEND (index.html)
--------------------------------------------------------------------------------

Структура интерфейса:
  - Трёхколоночный layout (grid: 320px 1fr 340px)
  - Левая панель: список команд с фильтрацией
  - Центральная панель: визуализация графа (Cosmograph)
  - Правая панель: детали выбранной команды (авторы и публикации)

Основные компоненты:

1. Левая панель (Команды):
   - Выбор периода (select)
   - Поиск команды по автору (input + кнопки "Найти"/"Сброс")
   - Список команд с информацией:
     * ID команды
     * Примеры авторов (первые 3)
     * Количество core/periphery авторов
     * Общее количество авторов

2. Центральная панель (Граф):
   - Визуализация графа соавторства (Cosmograph)
   - Два режима отображения:
     * Полный граф: все авторы периода (когда команда не выбрана)
     * Граф команды: команда + окружение (когда команда выбрана)
   - Панель инструментов (toolbar):
     * Размер узлов (range slider)
     * Толщина рёбер (range slider)
   - Кнопки управления:
     * Fit view
     * Zoom in/out
     * Пауза/Запуск симуляции
     * Переключение колец окружения (Окружение)
     * Переключение колец core авторов (core)
     * Переключение колец periphery авторов (periphery)
   - Модальное окно настроек симуляции:
     * Gravity (0-1.5)
     * Repulsion (0.2-4)
     * Link strength (0.1-4)
     * Link distance (2-60)
     * Friction (0.2-1.0)
     * Cluster repulsion (0.2-4)
     * Max authors per doc (0-500)
     * Include single pub (checkbox)
   - Модальное окно информации об авторе (при клике на узел):
     * Имя автора
     * ID, количество публикаций, статус
     * Кнопка для показа списка команд автора
     * Список команд автора в выбранном периоде
   - Визуальные индикаторы:
     * Анимированные кольца вокруг узлов (фокус, окружение, core, periphery)
     * Подсветка рёбер при наведении (toast с информацией)

3. Правая панель (Детали команды):
   - Заголовок с ID команды
   - Список авторов команды (с статусом core/periphery)
   - Список публикаций команды в периоде:
     * Название публикации
     * Год
     * Авторы с цветовыми индикаторами статуса

Цветовая схема:
  - core: #1b7f3a (зелёный)
  - periphery: #1a5fb4 (синий)
  - other: #9a9a9a (серый)
  - neutral: #d3d3dc (светло-серый)
  - accent: #0f6aeb (синий)
  - environment: #cc6600 (тёмно-оранжевый, для узлов окружения в графе команды)
  - link: #d3d3dc (серый, для рёбер)

Функциональность JavaScript:

1. State management:
   - periods: список периодов
   - teams: список команд
   - selectedPeriod: выбранный период
   - selectedTeam: выбранная команда
   - nodes/edges: данные графа
   - teamMembers: Map с ID авторов и их статусами в команде
   - graph: экземпляр Cosmograph
   - simulation: параметры симуляции
   - nodeSizeScale, edgeWidthScale: масштабы визуализации

2. Основные функции:
   - loadPeriods(): загрузка списка периодов
   - loadTeams(): загрузка списка команд с фильтрацией
   - loadGraph(): загрузка данных полного графа периода
   - loadTeamGraph(teamId): загрузка графа команды с окружением
   - buildGraph(): построение/обновление графа Cosmograph
   - selectTeam(teamId): выбор команды и загрузка деталей + графа команды
   - renderTeams(): отрисовка списка команд
   - renderAuthors(): отрисовка списка авторов
   - renderPublications(): отрисовка списка публикаций
   - applyTeamHighlight(): применение подсветки команды на графе
   - applySettingsValues(): применение настроек симуляции
   - showNodeInfoByIndex(index): показ модального окна с информацией об авторе
   - loadAuthorTeams(authorId): загрузка списка команд автора
   - focusPointByAuthorId(authorId): фокусировка на узле автора
   - updateFocusRing(): обновление анимированных колец вокруг узлов

3. Интеграция с Cosmograph:
   - Используется Cosmograph 2.0.0 из esm.sh
   - Настройки графа:
     * Размер узлов зависит от количества публикаций (pubs), диапазон: [3*scale, 14*scale]
     * Цвет узлов:
       - core: зелёный (#1b7f3a)
       - periphery: синий (#1a5fb4)
       - окружение (в графе команды): тёмно-оранжевый (#cc6600)
       - нейтральный (в полном графе): светло-серый (#d3d3dc)
     * Толщина рёбер квантуется по весу (1→1.1, 2→1.6, 3-4→2.0, 5-8→2.8, 9-16→3.2, 17-32→4.0, 33+→3.6)
       и умножается на edgeWidthScale
     * Цвет рёбер:
       - В графе команды: зелёный (оба в команде), оранжевый (команда-окружение), серый (окружение-окружение)
       - В полном графе: зелёный (оба в команде), серый (иначе)
     * Изогнутые рёбра (curvedLinks: true, 19 сегментов)
   - Управление симуляцией: пауза/запуск (собственное состояние simulationPaused)
   - Кнопки: FitView, ZoomInOut
   - События: onPointClick, onLinkClick, onLabelClick

4. Обработчики событий:
   - Изменение периода → перезагрузка команд (граф не перезагружается автоматически)
   - Поиск команд → фильтрация списка
   - Выбор команды → загрузка деталей и графа команды с окружением
   - Сброс поиска → очистка графа и показ placeholder
   - Клик на узел → показ модального окна с информацией об авторе
   - Клик на ребро → показ toast с информацией о связи
   - Клик на автора в списке → фокусировка на узле автора
   - Изменение размеров узлов/рёбер → обновление визуализации
   - Настройки симуляции → применение параметров (перезагрузка графа при изменении фильтров)
   - Переключение колец → показ/скрытие анимированных колец вокруг узлов

ОСОБЕННОСТИ РЕАЛИЗАЦИИ
--------------------------------------------------------------------------------

Backend:
  - CORS middleware настроен на разрешение всех источников (*)
  - Парсинг периода: функция parse_period() валидирует формат "YYYY-YYYY"
  - Сложные SQL запросы с CTE (Common Table Expressions)
  - Обработка ошибок: HTTPException для отсутствующей БД и невалидных параметров
  - Read-only подключение к DuckDB для безопасности

Frontend:
  - Все стили и скрипты встроены в один HTML файл
  - Использование ES modules для импорта Cosmograph
  - Сохранение позиций узлов при обновлении данных (preservePointPositionsOnDataUpdate)
  - Динамическое обновление графа без полной перезагрузки данных
  - Модальное окно для настроек симуляции
  - Модальное окно для информации об авторе (позиционируется в области графа)
  - Анимированные SVG кольца для визуализации фокуса и групп узлов
  - Toast-уведомления для информации о рёбрах
  - Placeholder при отсутствии графа

База данных:
  - Используется DuckDB (колоночная БД)
  - Данные о командах хранятся в таблице teams с периодами (скользящие окна)
  - Статусы авторов: 'core' (ядро команды) и 'periphery' (периферия)
  - Связь авторов и документов через таблицу auth_doc с порядковыми номерами

ВАЖНЫЕ ЗАМЕЧАНИЯ
--------------------------------------------------------------------------------

1. База данных lis.duckdb должна находиться в корне проекта
2. Приложение работает только в read-only режиме с БД
3. Периоды имеют формат "YYYY-YYYY" (скользящие окна)
4. Граф строится на основе совместных публикаций авторов
5. Фильтрация по max_authors_per_doc помогает избежать огромных клик в графе
6. Авторы с 1 публикацией по умолчанию исключаются из графа
7. Приложение поддерживает два режима графа:
   - Полный граф: все авторы периода (загружается через /api/graph)
   - Граф команды: команда + окружение (загружается через /api/teams/{team_id}/graph)
8. При изменении периода граф НЕ перезагружается автоматически (только список команд)
9. При изменении настроек фильтрации графа (max_authors_per_doc, include_single_pub)
   граф перезагружается, выбранная команда сбрасывается
10. При выборе команды загружается граф команды с окружением (все авторы публикаций команды)
11. Узлы окружения в графе команды имеют status = null и отображаются оранжевым цветом
12. Анимированные кольца вокруг узлов обновляются через requestAnimationFrame
13. При сбросе поиска или снятии выбора команды граф уничтожается и показывается placeholder

АНАЛИЗ ПРОИЗВОДИТЕЛЬНОСТИ
--------------------------------------------------------------------------------

Приложение включает детальное логирование производительности для анализа узких мест:

Backend (логи сервера):
  - Все запросы к графу логируют время выполнения:
    * Время выполнения SQL запроса для узлов
    * Время выполнения SQL запроса для рёбер
    * Время обработки данных на Python
    * Время сериализации JSON
    * Общее время обработки запроса
  - Для получения EXPLAIN ANALYZE SQL запросов добавьте параметр ?explain=true:
    GET /api/graph?period=2023-2025&explain=true
    GET /api/teams/{team_id}/graph?period=2023-2025&explain=true

Frontend (консоль браузера):
  - Все операции загрузки графа логируют время выполнения:
    * Время загрузки данных (fetch)
    * Время обработки данных (маппинг узлов и рёбер)
    * Время создания/обновления Cosmograph
    * Время загрузки данных в Cosmograph (dataUploaded)
    * Общее время загрузки графа
  - Логи выводятся в консоль браузера с префиксом [PERF]

Использование:
  1. Откройте консоль браузера (F12 → Console)
  2. Загрузите граф (выберите период или команду)
  3. Просмотрите логи [PERF] для анализа времени выполнения
  4. На сервере проверьте логи FastAPI для деталей SQL запросов
  5. Для анализа планов выполнения SQL используйте ?explain=true

Типичные узкие места:
  - SQL запрос для рёбер (JOIN doc_authors a1 JOIN doc_authors a2) - квадратичная сложность
  - Загрузка данных в Cosmograph (dataUploaded) - зависит от размера графа (~1+ секунда)
  - Cosmograph setConfig - обновление конфигурации (~1+ секунда)
  - Сериализация JSON больших графов

Оптимизации производительности:
  - Использование Map для поиска узлов по ID (O(1) вместо O(n))
  - Предвычисление и кэширование цветов узлов перед передачей в Cosmograph
  - Оптимизация функций pointColorByFn и linkColorByFn для избежания поиска в массивах

КОНФИГУРАЦИЯ И НАСТРОЙКИ
--------------------------------------------------------------------------------

Пути (определены в main.py):
  - APP_DIR: директория с main.py (teams_app/teams_app/)
  - PROJECT_ROOT: корень проекта (APP_DIR.parent.parent)
  - DB_PATH: путь к БД (PROJECT_ROOT / "lis.duckdb")
  - STATIC_DIR: директория со статикой (APP_DIR / "static")

Параметры по умолчанию:
  - Порт: 8000
  - max_authors_per_doc: 100
  - include_single_pub: False
  - nodeSizeScale: 1.2
  - edgeWidthScale: 1.2
  - simulation.gravity: 0.25
  - simulation.repulsion: 1.0
  - simulation.linkStrength: 1.0
  - simulation.linkDistance: 16
  - simulation.friction: 0.85
  - simulation.clusterRepulsion: 1.0
  - Размер узлов: диапазон [3*nodeSizeScale, 14*nodeSizeScale]
  - Автоматический fit view: через 4 секунды после загрузки графа
